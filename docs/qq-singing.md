# 让芸汐唱歌：歌声合成选型（2026-09-13）

需求：群里点歌时，她能**真的唱出来**（有旋律），最好还是她自己的声音。

## Phase 0 已实现（2026-09-13）

B 路线已经落地并跑通，线上开 `[qq_sing]` 即可用：

- **服务**：`tools/sing-service/`（`service.py` + `templates.json` + 验收工具 `verify_song.py`），
  默认 `127.0.0.1:6121`，只监听回环；依赖只有 numpy + praat-parselmouth。
- **机器人侧**：新配置段 `[qq_sing]`、新标记 `[[SING 模板id]]`（只在服务可用时下发）、投递复用
  语音消息的暂存目录与 NapCat 路径；失败按"唱歌 → 念歌词 → 打字"三级回退。
- **模板库**：小星星 / 两只老虎 / 茉莉花 / 自创·轻快 / 自创·慢板——只收公有领域或自创旋律，
  歌词由模型原创；`GET /v1/templates` 是唯一事实来源，提示词里的模板清单就来自它。
- **实测**：《小星星》全曲 14 个音，实际 9.27s vs 计划 9.23s（时值全部对齐），音高 12–13/14
  与目标一致（余下偏差来自分析器的采样点），渲染 5.9s、逐音响度拉平。
- **顺带改动**：语音服务新增按请求的 `speed`（唱歌按音符时值定长）与
  `--tts-noise-scale-w 0`（默认 0，让同一句话长度可复现——唱歌对齐音符依赖这一点；
  想要原来的时长随机感就把它调回 0.8）。

## 音质调优（2026-09-13 晚，线上听到"很恐怖"之后）

第一版上线后群里的评价是"克式恐怖"。把发出去的音频拿回来做了客观体检，问题不在
"唱得准不准"，而在三件事：

| 症状 | 实测 | 原因 | 修法 |
| --- | --- | --- | --- |
| 像幽灵小女孩 | 基频中位 **696Hz**（她说话是 248Hz），最高 1317Hz | 模板用了八度 5（C5–A5），比她自己高一个半八度；PSOLA 把 250Hz 的音色硬顶上去 | 模板整体降到**八度 4**（C4–A4，261–440Hz），正好贴着她说话的音区；实测新中位 348Hz，低频占比 44.9% ≈ 她说话的 43.9% |
| 一路咔哒 | 波形跳变 99.99 分位 0.48（她说话 0.22） | 单字内部"清辅音原速 + 变调元音"硬拼接；音与音之间硬拼接 | 字内 3ms、音与音 15ms 交叠拼接（连音），总时值用"多合成一个交叠时长"补回来；跳变降到 0.35，且有声处跳变密度 0.8/秒 ≈ 她说话的 0.9/秒 |
| 贴耳喊 | 峰值 0.92、RMS 0.25 | 整体归一化太冲 | 峰值收到 0.80，逐音响度对齐从 ±4dB 收到 ±2.5dB |

另外颤音从 1.2%/5.5Hz 降到 0.8%/5.0Hz 并加了 120ms 渐入，小星星 bpm 104→96、
自创·慢板 72→66。

第二轮（群里仍说"恐怖"）又做了一轮客观对比，找到两处更深的病根：

| 症状 | 实测对比她说话 | 原因 | 修法 |
| --- | --- | --- | --- |
| 又薄又尖 | 0–300Hz 胸腔 **20%**（她 35%），1–4kHz 硬度 **31%**（她 20%） | 旋律整体落在 C4–A4，基频高过她说话的 248Hz，胸腔共鸣整段落在 300Hz 以下被让出去了；PSOLA 又把能量堆到 1–4kHz | 新增整体**移调**（默认 -5 半音），把旋律中心压到 ~250Hz；再加三段 EQ：250Hz 低架 +4dB、3kHz −4.5dB、7kHz 以上 −5dB。结果：胸腔 **36%**、硬度 26%、谐噪比 20.3dB —— 与她说话的 35% / 20% / 20.3dB 几乎一致 |
| 一层"颗粒/嗡" | 30–100Hz 包络抖动 **27.9%**（她 16.7%） | 元音循环的接缝只有 4ms | 接缝加长到 12ms（循环单元是整数个音高周期，加长不会梳状滤波），并给每个长音加 3–6Hz、3–6% 的幅度微颤与 ±0.35% 的音高 jitter（真人唱歌两样都不为零，纯循环是"逐样本重复"） |
| 句间没有呼吸 | — | 逐音拼接到句尾直接进下一句 | 模板新增 `breath_after`，句末插 0.22s 换气 |
| 混响反而补毛刺 | 4–8kHz 占比不降 | 混响冲激用的是白噪声，往高频补了一层 | 冲激先做一阶低通再卷积 |

第三轮试听后定稿（2026-09-13 晚）：**移调 -5 半音、不加混响**。四版对比（原位/移调-5/
移调-8 × 有/无混响）里选了"移调 -5 无混响"——干声更贴她自己的音色，混响虽然让声音"像在
房间里"，但也把她的辨识度抹掉了一点。服务默认已改为关混响，临时想听带混响的可以用
`--reverb` 启动或请求里带 `"reverb": true`。

定稿版实测：胸腔 35% / 主体 34% / 硬度 24% / 毛刺 6%，谐噪比 19.9dB——与她说话的
35% / 27% / 20% / 18% / 20.3dB 基本重合；27/28 音命中，20.73s（计划 20.66s）。

经验：**"人力VOCALOID"路线里，旋律中心必须落在她说话的基频附近（实测 248Hz）**。变调幅度超过一个八度时，
哪怕共振峰保住了，听感也会立刻变成"非人"——这是这条路线最容易踩、也最容易修的一坑。

## 结论先说

| 路线 | 音色 | 音质 | 这台服务器跑得动吗 | 工作量 | 建议 |
| --- | --- | --- | --- | --- | --- |
| **B. 她的 TTS + PSOLA 变调拼接**（人力VOCALOID） | **就是她现在的说话音色** | 电子感、能听出在唱 | ✅ 已实测（1 秒渲染 3 秒音频，零新增常驻模型） | 2–4 天 | **Phase 0 先做** |
| A. DiffSinger（开源 SVS + ONNX 声库） | 声库音色（≠ 她，除非专训） | 最好（真正 SVS） | ⚠️ 内存见底，要 int8 + 按需加载或换机器 | 1–2 周 | Phase 1 |
| C. SVC（so-vits-svc / RVC 音色转换） | 她的（但需歌唱数据训练） | 依赖源唱 | ❌ CPU 太慢，且我们没有她的歌唱数据 | — | 不做 |
| D. 云端歌声/音乐 API | 不是她 | 好 | ✅（要联网/付费） | 1–2 天 | 兜底 |

推荐：**先 B 打通全链路，再按需上 A**。B 的音色就是她本人（保共振峰的 PSOLA 变调），代价是电子感；A 音质最好，但要先解决"声库音色不是她"和"这台机器没内存"两件事。

## 2. 四条路线

### A. DiffSinger（开源 SVS 引擎 + ONNX 声库）

- **事实**：[openvpi/DiffSinger](https://github.com/openvpi/DiffSinger) 是目前主流的开源歌声合成系统；社区有大量 ONNX 中文声库（唱法子模型：气声/力度/发声等）。
- 已有现成的远程推理服务：[openutau-remote-inference](https://github.com/AI-Hobbyist/openutau-remote-inference)（Apache-2.0），自动选择 `TensorRT → CUDA → DirectML → CPU`，带 `/release`、`/release_session` 按需释放模型内存，支持 fp32/fp16/int8。
- **但它不是完整渲染器**：它是给 OpenUtau 当前端用的推理后端（README 明确要求配合修改版 OpenUtau）。也就是说"乐谱 → 音素/时长/F0 → 声学 → 声码器"这条无头管线要我们自己搭。
- 声库授权逐个看：不少中文声库是**非商用**（例：[某声库使用须知](https://raw.githubusercontent.com/tuskinekinase/shisakunedemo_ds/refs/heads/main/LICENSE_zh)）。
- 音色问题：声库唱出来不是她现在的说话音色。想要"她的歌声"，得另训一个声库/VITS——而训练要 GPU（你自己的 Mac 可以，或租卡）和歌唱数据。
- 落点：这台机器要跑得先 int8 + 按需加载（几百 MB 峰值），更稳的是放到你的 Mac（Apple Silicon）上，服务器走隧道调用。

### B. 人力VOCALOID：她的 TTS + PSOLA 变调拼接 —— 已实测

做法（三行就说清）：

1. 逐字调现有 `/v1/tts`（每个字一次），拿到正常说话的音频；
2. 用 Praat 的 PSOLA 操作（parselmouth）把每个字的**基频改成音符频率**、**时长拉到音符时值**，共振峰保持不变 → 音色还是她；
3. 按音符顺序拼接，加颤音与短滑音。

实测（本机服务器，`/tmp/yunxi-sing-spike/xiaoxingxing.wav`）：

- 《小星星》第一句「一 闪 一 闪 亮 晶 晶」= C5 C5 G5 G5 A5 A5 G5；
- **渲染 2.8 秒音频只用 1.03 秒**（含 7 次 TTS 调用），CPU 峰值很低；
- 基频轨迹实测 6/7 个音落在目标音上（其余一个出现八度/五度跳变伪影，属于要修的工程细节）；
- 依赖只有 `parselmouth + numpy`（有 wheel，装进了独立 venv `~/yunxi-sing-spike/.venv`，**没有动生产 venv**）。

已知要打磨的点：个别音的八度跳变、字间辅音间隙、长音末尾不稳、连音（legato）粘连。都是参数级工作，不是路线级风险。

这条路线的价值：**音色延续人设**（她说话和唱歌是同一个声音），且不增加常驻内存占用——这是这台机器最缺的东西。

### C. SVC（so-vits-svc / RVC）

- 思路：先有一段"别人唱好的干声"，再用音色转换变成她的声音。
- 问题一：我们没有她的歌唱数据（只有 TTS 合成的说话音），用 TTS 数据训 SVC 通常学不到歌唱的 pitch 鲁棒性；
- 问题二：CPU 推理慢（一首歌几分钟起），这台机器扛不住；
- 结论：不作为第一步（[so-vits-svc-fork 在 PyPI](https://pypi.org/project/so-vits-svc-fork/) 可查，但部署门槛与算力都不匹配）。

### D. 云端歌声合成 / 音乐生成 API

- [ACE Studio 有对外接入文档](https://docs.acestudio.ai/ai-agent/external-agent-access.md)，许可与版权说明也在[官方文档](https://docs.acestudio.ai/docs/product-wiki-pt/apendice/license-and-copyright.md)；讯飞有[音色转换 API](https://www.xfyun.cn/doc/voiceservice/TimbreConversion/API.html)；Suno 类生成的是"整首歌"不是她的音色。
- 优点：不吃本机算力、音质好；缺点：音色不是她、要联网（境内机器访问境外服务要代理）、按次计费、服务条款与"用他人音色"的合规要逐条确认。

## 4. 旋律从哪来（比模型更容易被忽略的一半）

1. **曲库模板（推荐）**：内置一小把公有领域/自创旋律（小星星、两只老虎、茉莉花、送别…），每条带元数据：音节数、速度、情绪、声部。
2. **用户点歌**：按名字查模板；查不到就挑一条情绪接近的，并说明"我先唱这个"。
3. **模型写简谱**：可做但不可靠，必须校验（音符数 == 音节数、音域在模板范围内），失败就回退到模板。
4. **词曲对齐**：`pypinyin` 切音节，一字一音；多音字/儿化/衬词走模板的例外表。

合规：只唱**公有领域或自创旋律**；歌词让模型原创，不要复制受版权保护的词曲。

## 6. 资源与运维

- B 路线**不新增常驻大模型**：合成服务只需 `parselmouth + numpy`；现有 TTS 进程复用。
- 一次点歌的额外开销约等于"逐字 TTS × 字数 + 变调"，实测 1 秒级；可以给出 10–20 秒的等待提示。
- A 路线落地时：int8 + `/release` 按需加载，或把服务放到 Mac（要在线 + 隧道 + 鉴权），并把它计入内存预算。

## 7. 合规

- 曲目：公有领域/自创旋律，原创歌词；翻唱现有流行歌有版权风险（尤其发在群里）。
- 音色：现有 `vits-zh-ll` 的训练数据来源上游未完整声明（`tools/speech-service/README.md` 已注明），商用前必须确认；A 路线选声库同理。
- 云端：条款、数据出境、"非本人音色"是否允许，逐条确认后再接。

## 9. 需要拍板的问题

1. **音色**：必须是她现在这个声音（→ B 立刻可做；A 要等 Phase 2），还是"好听的歌声"就行（→ A/D）？
2. **曲目**：只唱公有领域/自创旋律（安全），还是要能点现有流行歌（版权风险自担）？
3. **落点**：Phase 1 跑在这台 4C/3.7G 服务器（要 int8 + 按需加载，可能还要加内存），还是你的 Mac？
4. **延迟**：一条 20 秒的歌等 10–30 秒可以接受吗？
5. **预算**：要不要用花钱的云端服务（D）？
