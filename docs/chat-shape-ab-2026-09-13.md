# 私聊对话形状：契约对照实验（2026-09-13）

改动的目标是消除"一问一答感"。生产指标（同会话连续气泡占比、提问占比、
续聊登记率）要等真实聊天才有数据，但**最容易失败的地方是模型不照做**：
新契约要求它在该停的时候说停、该补一句时用 `[[BUBBLE]]` 拆开，如果模型
根本不理会，后面所有宿主逻辑都是空转。所以在真实私聊流量到来之前，先用
固定场景把两种契约各跑一遍，把"模型到底会不会照做"钉死。

复现命令（契约文本从 `plugins/model/src/yunxi/core_model.rs` 现取，脚本不会
和线上指令漂移）：

```bash
python3 scripts/chat_shape_ab.py --trials 4 --token-file <含 BOT_API_TOKEN 的文件> \
    --json /tmp/chat_shape_ab.json
```

## 结果（deepseek-v4-flash，7 个私聊场景 × 4 次 = 每种契约 28 条）

| 契约 | 样本 | 提问率 | 多气泡率 | 未完句率 | 均条数 | 均字数 |
| --- | --- | --- | --- | --- | --- | --- |
| legacy（改动前的"只写一条"） | 28 | 50% | **0%** | 0% | 1.00 | 84.9 |
| current（本次改动后） | 28 | 82% | **29%** | 0% | 1.32 | 87.8 |

关键在**多气泡那一列**：legacy 契约下 28 次里 0 次出现第二个气泡——这不是
模型不想，而是契约不允许，宿主也就永远只能一问一答。current 契约下七个
场景里有五个出现过第二个气泡，而且**用不用气泡跟着答案长度走**：

| 场景 | current 契约下的气泡数（4 次） | 字数 |
| --- | --- | --- |
| 情绪承接（被领导说了） | 1, 1, 2, 2 | 66–76 |
| 低落（觉得自己没用） | 1, 1, 1, 2 | 73–125 |
| 悬念邀请（你猜遇到谁） | 1, 2, 1, 1 | 30–37 |
| 日常闲聊（牛肉面） | 2, 1, 1, 1 | 31–58 |
| 分享近况（提交了重构） | 全 1 | 37–64 |
| 明确提问（帮我看看报错） | 全 1（先要上下文，不拆） | 70–125 |
| **需要展开（讲讲你怎么想）** | **2, 1, 2, 3** | **207–243** |

也就是：短互动和事实问答仍然一条说完；**只有"需要展开"这类真的要说一段
的场景才用满气泡预算**，最长的一条 243 字被拆成 3 段。这不是靠宿主硬切，
是模型按契约自己判的——"想到第二句"和"答案太长"是同一套机制。

## 老实说：提问率这一项经过两次修正

2 次/场景的初次跑分是 `52% → 83%`；加到 5 次/场景（6 个场景）变成
`52% → 57%`；再加到 4 次/场景并补上"需要展开"场景（7 个场景）是
`50% → 82%`。样本量在这个量级上，提问率会在 55%~83% 之间跳，**不能用它
下结论**；能下结论的是多气泡那一列（legacy 恒为 0，current 稳定在
20%~29%），因为那是结构性的、不靠统计显著。

提问率的真实收益也不是"从不说变成常说"，而是**问句可以被拆成独立的一条**，
以及宿主从此有据可依（`asks` 遥测 + 续聊登记），不再依赖模型自觉。
均字数 84.9 → 87.8 说明"默认一条、说清就停"没有被放开成啰嗦。

## 已知边界（下一轮再看）

1. **截断**：这 28 条在线上同一档 `max_output_tokens=1200` 下没有出现未完句
   （`finish_reason=length` 的样本）。截断是在输出预算被压到 300 时才复现的，
   所以它属于"长答案 + 小预算"的边界，不是常态。契约里已经写明长答案要摊到
   1–3 个气泡里，宿主侧另有 `reply_looks_complete` 兜底：不以保证句读结尾的
   回复不会被登记续聊，避免半句话之后又接半句话。
2. **统计口径**：提问率在小样本下会从 50% 跳到 82%（见上），要下结论得等生产
   数据（`scripts/verify-chat-shape.sh` 的"提问占比"一栏）。多气泡率是结构性
   差异，可以直接用。
3. `呢` 没有算进"说完"的结尾标记：它经常是半句（"那我呢"），漏判一次续聊
   比在断句后追一句更安全。
