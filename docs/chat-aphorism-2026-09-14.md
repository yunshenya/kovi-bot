# 情绪话题上的"格言体"：要接住人，不是给道理（2026-09-14）

触发是一张群聊截图。对方（不忻）把自己的去留拿出来问，她五问五答，最后群里的话是
"像这种直接戛然而止的有点不好"。

## 诊断：不是"戛然而止"，是答错了对象

把那段原话摊开看（2026-09-14 22:07~22:10，群 641996763）：

```
22:07:57  不忻：你觉得人怎么走会更能接受一点
22:07:58  她：  怎么走都会疼吧，但安静点、没吵没闹的那种，事后想起来会好受些。
22:08:29  不忻：这样直接消失好吗 我挺犹豫的
22:08:30  她：  直接消失，对方会一直悬着，不知道发生了什么，那种难受比一句告别还长。
22:09:16  不忻：怎么样才能再也不回来
22:09:20  她：  真能再也不回来的地方，其实没有。人走了，痕迹还在别人心里挂着。
22:09:21  她：  所以别想着彻底消失，想清楚要放下什么，比想清楚去哪更要紧。
22:10:14  不忻：怎么样放下
22:10:16  她：  放下不是忘掉，是想起的时候不再疼了。
```

他在说"我挺犹豫的"——他在犹豫要不要走。**她六条回答，全是"人怎么走比较好"的普遍
道理，没有一句是关于"你"的**：六条里一个"我"、一个"你"都没有。"戛然而止"是结果：
一句放到谁身上都成立的话，本来就没有下一句可说。

## 根因：上一轮打掉的是条目式百科体，这一轮是它在情绪话题上的第二形态

`HUMAN_CHAT_STYLE` 的前七条合谋出了这个形态：

1. 第 1、6 条要短、要"说完就停" → 一条就够，不需要第二条；
2. 第 6 条禁"拔高收尾"，但**没禁"整条就是拔高"** → 绕法就是把整条写成格言；
3. 第 7 条禁反问收尾，可见回复契约里还写着"不要为了显得热情或留住话头而追问"
   → 收尾手段只剩"句号 + 停"。

讽刺的是解法早就在提示词里：可见回复契约写着"**先接住对方情绪、再补一件具体的事**，
可以写成两个气泡"——但前提被限定成"确实有两件彼此独立的事要说时"，还要同时对抗
"不要留住话头"，模型选了保守的一边（实测那一轮 `bubbles=1`、`directive=None`）。

## 改动

`plugins/model/src/model/chat_style.rs`：

- 新增第 8 条：对方问的是他自己的事时，**先把话落回他身上**——回答里要有一处只对他
  成立；并明确"落回他身上不是替他下结论"（第一版 A/B 出过「真放下的人不会问怎么放下」
  这种挤兑句）。
- 新增第 9 条：这种时候"说完就停"不适用，可以再补一条做三件事之一——说自己的反应、
  把选择权递回去、承认接不住；**并写明这三样都不是追问**（否则与上面那句"不要留住
  话头"直接冲突）。附带一条跨条约束：连着两三条都在讲道理时，下一条换成具体的。
- 第 2 条补一句收尾口径：句尾可以不加句号，但**别停在半句上**。
  （原因见下面"无尾标点不是截断"。）

`plugins/model/src/yunxi/core_model.rs`：把那句"不要为了显得热情或留住话头而追问"
补上边界——"留话头不靠提问"。

## 量化口径

判据只在 `scripts/chat_shape_ab.py` 里实现一次，A/B 与生产监控（`verify-chat-shape.sh`
的 `--from-log`）共用，不各抄一份：

- **议论率**：命中格言/议论句式（"不是A是B""比X更…""越…越""怎么…都"…，以及"含泛指词
  且全句没有我/你"）。自检样本是线上那六条格言，**六条必须全中**，否则脚本直接拒绝运行。
- **落到人**：正文里出现"我"或"你"。这是"有没有接住他"的最直接标记。
- **真截断率**：`finish_reason=length`。这才是"被输出预算掐断"。
- **无尾标点率**：结尾没有收尾标记。**不是缺陷指标**（见下）。

## 老实说

1. **"无尾标点"不是缺陷，指标一开始把它和截断混为一谈了。** 第一版 A/B 报了
   "未完句率 27% → 39%"，看着像回归；查下去发现那些"未完成"的结尾是
   `想说就说说，我在这儿` / `不想说也行，我在这儿呢` / `我帮你看是哪类问题`——
   **正是这次要加的形态**，只是句尾没标点，而契约本来就允许"句尾可以不加句号"。
   现在工具同时报 `finish_reason=length`（真截断，两轮都是 0%）与"无尾标点率"，
   不再把正常口语收尾算成错误。
2. **`complete=false` 的真实代价只有一个**：`reply_looks_complete && reply_asks_something`
   是宿主"给不给一次自动续聊"的判据，所以口语收尾会少拿一次续聊。没有别的用户可见
   后果（另一处用途是 turn shape 遥测）。这里选择"宁可少给一次续聊"——真正的截断信号
   `finish_reason` 在这一层拿不到，而半句话之后再追半句更难看。
3. **续聊机制与契约存在结构性张力**（这一轮没动，记在这里）：只有"完整 **且** 有提问"
   才换来一次自动续聊，而第 7 条把问句压到"十条里最多一两条"。也就是说她几乎不可能
   靠"我在这儿"这种收尾赢得第二拍。要不要为情绪话题开一档（比如"回复落到人且足够短"
   也算留了话头），应该单独立项、单独量，而不是顺手改。
4. **反例不带真实话题**：契约里的新例子用的是中性情绪场景（"难过的时候，时间会替你
   把它磨平的" / "人总要学会自己跟自己和解"），没有把那次对话的具体话题写进去——
   测试里有断言守着这条（模型见过真实话题之后容易往上靠）。
