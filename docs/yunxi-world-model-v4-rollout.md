# Yunxi World Model v4 渐进实施路线（Rollout）

> **配套文档**：[`yunxi-world-model-v4.md`](./yunxi-world-model-v4.md)（权威设计蓝图，含 §0.1 实现状态对照）。
> **目标**：按“对你价值密度”排序，把 v4 从设计蓝图逐步落地为“温柔芸汐 + Neuro-sama 技术”的脑部能力；
> 每一步都可独立回退、可观测、有界，且**不得阻塞正常聊天**。

## 0. 三条铁律（每条改动必须满足）

1. **有界**：所有新增状态/预测/模拟都带容量、预算、冷却与截止；失败走降级/熔断（v4 §132–138、§248–256）。
2. **可回退**：新增认知全走**影子模式**（v4 §217/§220：只记录“如果启用会怎样”的指标），达标才 active；一个 flag 就能关。
3. **不阻塞**：WorldModel 相关失败永远 fail-soft，绝不拖慢回复（v4 §249–255）。

## R0 ✅ 已实现（当前基线）

| 能力 | 说明 | 代码 |
|---|---|---|
| 世界“事实”最小闭环 | 传感器/事件 → `observe_world_fact` → Fact 记忆 + 开环 + Mind interest | `memory.rs::world_fact_draft`、`yunxi/mod.rs::observe_world_fact` |

| 自主/主动/多气泡治理 | 自治续聊默认 Wait、近重复合并、日志降噪 | `autonomous.rs`、`message_actions.rs` |

## R1 世界传感器泛化 + 主动关心（≈1 周）

- **目标**：把“你的世界”喂得更全：CI/构建状态、日历/日程、文件变更（v4 §139–147 一个最小实现）。
- **范围**：`world_sensors.rs` 新增 `file_state`（文件存在/变更）与复用 `command` 覆盖 CI；`observe_world_fact` 加 `interest_topic` 串联（已有参数）。
- **验收**：配置 2 个传感器 → 状态变化 → 24h 内她在合适对话/主动里自然提及；无刷屏（受主动配额限制）。
- **预算**：每传感器 ≤1 次外部调用/轮询周期；总量计入 traffic 上限。
- **影子/开关**：`world_sensors.enabled` 已支持；先观察 1 周再放大。

## R2 Situation 极简版（≈1–2 周，价值密度最高）

- **目标**：让核心知道“现在是什么局面”并影响时机——忙/安静/讨论中/计划中（v4 §21–26 的最小子集）。
- **范围**：新 `situation` 状态（进程内 + Postgres 小表）；从事件/事实推导（非大模型）：群活跃度、与 owner 最近交互、开环数量；作为**高显著度世界事实**注入回复上下文 + 参与主动选择。
- **验收**：同一局面下她的开口时机明显不同（群讨论中更安静、你忙碌时更克制）；`#情境` 可查当前局面。
- **预算**：确定性规则推导（0 模型调用优先），最多 8 个活跃情境。
- **影子/开关**：`[situation] shadow=true` 先记录。

## R3 SocialScene 极简（≈1–2 周）

- **目标**：群聊“谁在跟谁说话、刚谁被点名、有没有碰撞”，让接话更自然、不抢话（v4 §68–72 子集）。
- **范围**：由现有群消息事件推导（点名、回复关系、时间窗），不打大模型；抑制“刚被打断又插话”、优先接住@自己的人。
- **验收**：群聊下她不再连续接多位成员的话（对比 7 连发场景）；出现“抢话”场景明显减少。
- **优先度**：与 R2 并行，都在“时机/场合感”层。

## R4 时机决策接入 Executive（≈1 周）

- **目标**：把 R2/R3 的“场合”作为**软信号**喂给 Executive（v4 §93–95、§112–115），替代纯概率/冷却拍板。
- **范围**：`executive` 打分时读入 situation/socialscene 摘要；冲突/注意力预算优先。
- **验收**：主动/插话的“合理性”打分与场合一致；无回归（对比现有 cooldown 行为日志）。
- **注意**：**不**让 Executive 保存完整世界（v4 §229），只读快照。

## R5 Prediction 有限版（≈2 周）

- **目标**：在高价值动作（主动开口、提醒、工具执行）前，做**一次**“后果预测”并交给仲裁（v4 §46–52、§119 避免三次 LLM）。
- **范围**：仅“高价值”动作触发；预测结果进 `DecisionFormula`（v4 §231）；预测失败即跳过（不阻塞）。
- **预算**：预测调用 ≤ 每日 OCR（复用每日成本预算）；缓存按 fingerprint（v4 §122）。
- **影子**：先 shadow 记录“预测 vs 实际”，校准后再影响行为（v4 §123）。

## R6 Simulation / 反事实（≈2–3 周，最后才动）

- **目标**：对**不可逆/高后果**候选（群发、删除、对外承诺）做有界沙盒推演（v4 §53–67）。
- **约束**：仅 `ExecutionMode` 允许的候选；严格 budget/depth/cache；不真实执行（v4 §58、§161）。
- **验收**：危险候选被拦截或降级；普通聊天零模拟（v4 §60）。

## R7 Causal / Hypothesis（远期，价值密度低）

- 等 R1–R6 稳定、预算模型就绪后再做；先解决“事实 vs 假设 vs 未知”的**显式标签**（v4 §13、§32–33）——这是高价值低成本的早期切入，其余后置。

## R8 Persistence / Store（贯穿）

- 每个新增状态在其 active 前先有**持久化+删除边界**（v4 §125–131、§241–243）：`#删除我的数据` 一并清除；新表一律 `CREATE TABLE IF NOT EXISTS` + advisory-lock 迁移（沿用 `schema.rs` 模式）。

---

## 建议的 MVP 组合（先跑通“懂你”）

**R0（已有）+ R1 + R2 + R3 + R4**：她持续知道你世界的关键走向，且**开口时机有依据**——这是“活人味儿”增量最大的组合，2–4 周可上线。R5/R6 待成本预算与影子指标就绪后再开。

## 每步验收时的观测项（复用 v4 §154/§220）

- 影子模式下 `would_act/did_act` 一致性；
- 主动/插话的“时机合理性”人工抽样；
- 调用预算（每日模型调用数、token 量）；
- 高价值动作的失败/降级率。

> 一句话：**先做“场合 + 时机 + 世界感知”（R1–R4），别急着上预测/反事实。**
