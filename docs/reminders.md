# 定时任务

定时任务是机器人自己的持久化任务，不依赖当前聊天回复，也不会因为新消息到达而被打断。
任务保存在 PostgreSQL，进程重启或多实例部署后仍会继续扫描到期任务。

新闻摘要只是一个任务指令示例，不是独立的任务类型。任务分为两种：

- `message`：到点发送固定正文，适合“提醒我吃饭”“叫我起来活动”。
- `task`：到点重新执行一条自然语言动作指令，适合搜索、查询、整理、分析，以及调用已授权的 MCP 工具。

用户可以直接说：

- `10 分钟后提醒我起来活动`
- `明天早上提醒我吃饭`
- `明天早上搜索早间新闻，整理 5 条发给我`
- `明天早上查一下上海天气，告诉我是否需要带伞`
- `每天早上 8 点查询我的日历，告诉我今天最早的安排`
- `每天晚上 8 点把今天的重要对话整理成三点`
- `查看我的提醒`
- `明天早上不用提醒我了`

目标会话由创建任务时的当前私聊或当前群自动确定，模型不能指定任意 QQ 号或群号。群聊中的任务
由创建者才能取消；取消通过任务编号完成。用户说“明天早上不用提醒我了”时，模型会先列出当前
会话的未完成任务，再按编号调用取消工具；有多个候选时会先询问，避免误删。

`task` 到期后才执行保存的 `instruction`，因此“明天早上搜索新闻”不会把今天的搜索结果保存下来；
新闻来源数量、筛选条件和输出格式都直接写在这条指令里。
默认可用的定时工具是当前时间、公开网页搜索、受 SSRF 防护的网页读取和当前会话记忆查询。任务不能
创建、查看或取消其他定时任务，也不能执行清单外的工具。定时任务结果会去除内部思考和动作协议，并受
配置的输入、输出、工具轮数和执行租约限制。`message` 字段对 `task` 可作为发送时的标题前缀。

如果确实需要调用外部 MCP 服务，必须在对应服务配置中显式设置 `allow_scheduled = true`，且只把可信、
必要的工具放进 `allowed_tools`。这表示部署者明确授权该服务在无人在线确认时运行；不要对不可信服务开启。
例如：

```toml
[[tools.mcp_servers]]
name = "calendar"
command = "/opt/kovi/bin/calendar-mcp"
allowed_tools = ["list_events"]
read_only = true
allow_scheduled = true
```

没有 `allow_scheduled = true` 的 MCP 工具仍可用于普通对话，但不会出现在定时任务的工具清单中。
定时任务不是任意代码执行器；需要副作用时，应把动作封装为专用 MCP 工具，并通过配置显式授权和最小化
参数范围。

提醒时间以 `reminders.default_timezone` 为默认时区。数据库保存 UTC 时间和原始 IANA 时区；相对时间由
服务端计算，绝对时间由服务端验证。没有明确时间时，“早上”“中午”“晚上”默认按 `08:00`、`12:00`、
`20:00` 解释，并在创建成功回复中给出完整日期、时间和时区。

调度器使用 PostgreSQL `FOR UPDATE SKIP LOCKED` 和租约 token 原子领取任务。发送失败时按有限次数重试；
任务发送、数据库状态更新之间无法与 OneBot 组成分布式事务，因此极端崩溃场景采用至少一次投递语义。
已发送、取消或失败的终态记录会按 `memory.retention_days` 自动清理。
