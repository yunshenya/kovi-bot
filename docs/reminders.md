# 提醒任务

提醒是机器人自己的持久化任务，不依赖外部 MCP 进程，也不会因为当前回复被新消息打断。
任务保存在 PostgreSQL，进程重启后会继续扫描到期任务。

用户可以直接说：

- `10 分钟后提醒我起来活动`
- `明天早上提醒我吃饭`
- `明天早上搜索早间新闻，整理 5 条发给我`
- `每天早上 8 点搜索科技新闻发给我`
- `每天晚上 8 点提醒我吃药`
- `查看我的提醒`
- `取消提醒 #123`

模型会把请求转换成内置工具调用。目标会话由当前私聊或当前群自动确定，模型不能指定任意
QQ 号或群号。群聊中的提醒由创建者才能取消，群管理员删除本群数据时会删除本群全部提醒。

新闻任务不是保存一段固定文本，而是保存 `news_digest` 类型、搜索条件、来源数量和时区。
到期后调度器才搜索当天的公开网页结果，再调用模型整理标题、摘要和来源链接，最后发送到
创建任务的当前会话。没有明确时间时，“早上”按 `08:00` 处理；创建成功的回复会给出完整的
日期、时间和时区。搜索失败、摘要失败或发送失败会使用同一任务的租约和有限重试，不会把
搜索正文长期写入数据库。

提醒时间以 `reminders.default_timezone` 为默认时区，生产环境应按部署者和用户实际使用的时区
配置。数据库保存 UTC 时间和原始 IANA 时区；相对时间由服务端计算，绝对时间由服务端验证，
避免模型直接写入不可信的时间戳。

调度器使用 PostgreSQL `FOR UPDATE SKIP LOCKED` 和租约 token 原子领取任务。发送失败时按有限
次数重试；任务发送、数据库状态更新之间无法与 OneBot 组成分布式事务，因此极端崩溃场景采用
至少一次投递语义。已发送、取消或失败的终态记录会按 `memory.retention_days` 自动清理。
