# 群里 @ 她却被静默：判定依据的缺失（2026-09-14）

## 现象

2026-09-14 22:26~22:27，群 641996763：

```
22:26:20  不忻：@ 给我写一个看图软件用C语言          → 她回了
22:26:37  不忻：回复+@ 直接给我代码                  → 她回了一大段代码
22:27:10  不忻：@ 真能用吗？                        → 没有回
```

日志里那两条对应的行是：

```
22:27:10 [INFO] 群聊消息指向其他成员，仅观察不回复 (群组: 641996763, 用户: 2504679636)   ← Host 链
22:27:10 [INFO] 群聊消息指向其他成员，仅观察不回复 (群组: 641996763, 用户: 2504679636)   ← Core 链
```

## 判定是怎么做出来的

两条链路各自只看两件事：

```rust
if !addressed_to_bot          // message_at_self：at 段的 qq 是否等于她自己的号
   && directed_at_others(msg) // 只要带 at / reply 段就算"有指向"
{ 只观察不回复; return; }
```

于是：**消息带 at/reply 段、而 at 的目标不是她的号 → 整条静默**。她连"看一眼再决定"
的机会都没有。

## 规模

| | |
| --- | --- |
| 近 24 小时这条判定触发 | 305 次（两条链路各打一条，去重约 150 条消息） |
| 18:00 起去重后 | 86 次 |
| 其中发生在**她发言后 120 秒内** | **41 次（48%）** |

最后一行才是问题：**"她刚说完、别人回她、被静默"占了一半**。注意这 41 次里有多少是
真在叫别人，目前**无法判断**（见下）。

## 卡在哪：判定没有依据

`Message::to_human_string()` 对**任何人的 @** 都只渲染成 `[at]`，所以日志里看不出目标
是谁——`InboundMessage.directed_at_other_members` 的字段注释自己就写着"离线采集聊天
记录时无法从日志还原到底在叫谁"。

而目标恰恰是判定成立的**唯一**依据：

- `at=[别人的号]` —— 规则按设计生效；
- `at=[]`（悬空 @：段在、目标不在，QQ 客户端会发出这种段）—— 规则**误伤**；
- `at=[她的号]` —— 那就是 `message_at_self` 匹配失败，属于 bug。

三种情况在旧日志里长得一模一样。当时能确定的只有"她自己的号"和"消息里有哪些段"，
所以这次能做到的只是**逐个证明管道清白**，无法给那次静默定性。事后查不到的还有另一半
原因：模型调用轨迹是内存环形缓冲（64 条、不落盘），原始输出早被后续聊天冲掉。

## 这一轮做了什么（A + C）

**A. 判定补上依据**（`efea3dd`）

新增 `addressing_evidence(message, self_id)`，渲染成 `at=[...] reply=... self=...`；
悬空 @ 记 `?`，没有定向段记 `at=[]`，最多保留 4 个 at 目标。两条链路的日志都用它，
Host 链那条另外带上三个判定结果：

```
(群组: 641996763, 用户: 2504679636, at=[2504679636] reply=none self=<她的号> at_self=false reply_to_self=false named=false)
```

**C. 可见回合的模型原始输出留档**（`5b03dc2`）

同一时段的另一个毛病：她那条代码回复发出去时 `argv[0]` 变成 `argv0]`、正文里残留一行
`BUBBLE]]`、原始 1468 字只剩 1322 字。查不动的原因是**没有原文**。现在只要一轮可见
回复的内容被动过（sanitize 剥掉过内容，或正文比原始输出少超过 120 字节），就把原始
输出按 4000 字节有界留档一行，可以和实际发出的正文直接 diff。线上 24 小时 152 个可见
回合里 14 次命中，不会刷屏。

## 还没做的：B（需要先攒证据）

`directed_at_others` 的语义是"只要带定向段就算指向别人"，它把**解析不出目标**也算成了
"别人"。合理的收窄是：只对**能确认指向别人**的 at/reply 才算数，解析不出目标时不要静默
丢弃（fail-open），交给后面的限流与对话焦点机制去管。

这是行为改动——她可能开始接一些本该沉默的话——所以先等 A 的日志攒一周：把
`at=[...]` 为空、或 `at=[她自己的号]` 却仍然被判成"指向别人"的那些捞出来，看清楚误伤
的比例再动。判据都在这条日志里，不需要再翻代码。

## 顺带记住的两件事

1. `message_at_self` 只看 `at` 段，**不看 `reply` 段**（引用她的消息不会让她被"点名"）。
   Host 链另有一条"引用最近一条她的回复"的识别（`recent_agent_reply`），Core 链那条
   提前返回没有用上它——两条链路的判据并不完全对称，B 方案要一并核对。
2. 同一个 `message_at_self` / `directed_at_other_members` 在仓库里有三份实现
   （`model/group.rs`、`yunxi/bridge.rs`、`agent_tasks.rs`）。这次没有合并它们——那属于
   另一件事，但改判定语义时必须三处一起看，否则线上行为会按链路分裂。
